# VQ-003 live reads — effective emissionFactor in gvrp_db (2026-10-14)

Method: read-only queries via dbhub MCP (`execute_sql`, readonly=true,
max_rows=500) as `agent_reader` (SELECT-only). Smoke HTTP transport used
for this session; project config is stdio (` .opencode/dbhub.toml`).

## Q1 — per-branch e distinct values

```sql
SELECT branch_id, COUNT(*) n,
       COUNT(DISTINCT JSON_EXTRACT(vehicle_features, '$.emission_factor')) ne,
       GROUP_CONCAT(DISTINCT JSON_EXTRACT(vehicle_features, '$.emission_factor')) es
FROM vehicle_types GROUP BY branch_id
```

Result: 10 branches. 9 uniform single value 12.3 (branch ids
1, 2, 100, 300, 1001, 1002, 1003, 1004, 9000). Branch 1000: n=4, ne=4,
es = 0.0, 105.0, 190.0, 350.0.

## Q2 — branch names + NULL check

```sql
SELECT id, name FROM branches WHERE id IN (1,2,100,300,1000)
-- 1000 = 'Branch Huge 1'
SELECT COUNT(*) null_features FROM vehicle_types
WHERE vehicle_features IS NULL
-- null_features = 0
```

## Q3 — live fleet mix, Branch Huge 1

```sql
SELECT t.type_name,
       JSON_EXTRACT(t.vehicle_features, '$.emission_factor') e,
       COUNT(*) n
FROM vehicles v
JOIN vehicle_types t ON t.id = v.vehicle_type_id
JOIN fleets f ON f.id = v.fleet_id
WHERE f.branch_id = 1000
GROUP BY t.type_name, e
```

Result (3000 vehicles): xe tai 5 tan 350 (n=1000); Xe tai van Ford
Transit 190 (n=693); Xe may xang giao hang 105 (n=644); Xe may dien
giao hang 0 (n=663).

## Reading guidance (do NOT overclaim)

- These are point-in-time reads, not an experiment. They say which `e`
  the engine would receive per branch today, nothing about effectiveness.
- 180 appears nowhere in live data; it explains pre-452d0c5 job logs only.
- Zero NULL rows today does not retire KI-031 (direct engine callers can
  still send null; the unguarded unbox path is unchanged).
