- path templates plus parameters;
- bearer header, 15 s timeout;

- a 401 on an authenticated call clears the token and calls `AuthController.sessionExpired()`;
- an authenticated call without a token is treated as a 401 without a request.

`features/auth/auth_controller.dart`, login outcomes:
- role ≠ `DRIVER` → `notDriver`, nothing stored;

## Security-Relevant Changes

- **Cleartext:**
  - only debug builds reference `network_security_config.xml`;
  - it allows `10.0.2.2` only, without subdomains, and holds a commented LAN placeholder;
  - main, profile and release keep the Android default (no cleartext);
  - no TLS or hostname check is disabled anywhere.
- **Permissions:** `INTERNET`, `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`. No background location.
- **Storage:**
  - only the access token is persisted, in `flutter_secure_storage` (Android Keystore);
  - route data, customer data, positions and the "location explained" flag live in memory only;
  - there are no shared preferences and no database.
- **Session:** any 401 on an authenticated call clears the token and returns to Login. Logout clears the token. A non-DRIVER login stores nothing (DT-03).
- **Logging:**
  - `AppLogger.http` takes only method, path template, status or error kind;
  - `ApiClient` never logs bodies, headers, parameter values or exception messages;
  - DT-13 checks the log output and `print`/`debugPrint` during six failing calls.
- **External navigation:** none. `url_launcher` is used once, with `tel:` only (DT-11, DT-12). There is no OSRM, Directions, `geo:` or Maps intent, Google Maps SDK or API key.
- **Data leaving the device:** only the Entry API calls and OSM tile requests. Tile requests reveal the viewed map area to the tile server (development only, see Remaining Uncertainty). No analytics or crash reporting. `flutter --disable-analytics` was run for the Flutter tool on 2026-10-27; this is tool telemetry, not app behaviour.
- **Dummy values in tests:** the tests use invented values: `fake-token-for-tests`, `not-a-real-password`, username `taixe_thu`, branch "Chi nhánh Thử", phones `09000000xx`, coordinates near 10.0/106.0. These are not accounts or tokens of any system; they only feed the mock backend and DT-13. **The reviewer should confirm that this matches the task's "no test accounts, passwords or tokens in any file" rule.** The values can be generated at run time if required.
- **No backend change.** The Entry API sources were read only.

## Deviations From Design

None changes behaviour required by `design.md`. Each one is a refinement or a choice the design left open:

1. **Layout additions:**
   - `lib/theme.dart` and `lib/widgets/common.dart`;
   - `lib/core/log/app_logger.dart`: the task asks for "the app's own logger";
   - `lib/features/routes/phone_caller.dart`: so that DT-11 can intercept the launch.
2. **Login errors:**
   - design §6 maps 401 to "logout"; on the public login call there is no session, so a 401 there is shown as "Sai chi nhánh, tên đăng nhập hoặc mật khẩu.";
   - other 4xx on login show the generic client message;
   - a 400 with `RESOURCE_NOT_FOUND` (unknown branch) is a credentials error.
3. **Extra strings ([ui], not in `ui-design.md` §5):**
   - `routeFinished` "Đã đến điểm cuối của tuyến.";
   - `showPassword` / `hidePassword` (tooltips);
   - `osmAttribution` "© OpenStreetMap".
4. **Finished state:** after the last stop, the next-stop card shows `routeFinished` and the guidance card is not built. Only "Quay lại" remains.
5. **Follow-me button:** it sits at the top-right of the map, not bottom-right above the sheet, because the sheet's top edge moves with dragging.
6. **Camera fit:** the bottom padding includes the half-screen sheet, so all stops are visible above it.
7. **Numbers:**
   - a stop marker shows `sequence_number`, or the list index when it is null;
   - the next-stop counter is `{next stop index}/{number of legs}`.
8. **Decoder strictness:**
   - geometry that decodes to fewer than 2 points, or is malformed, uses the dashed fallback;
   - the decoder also rejects out-of-range coordinates and numbers longer than 6 chunks.
9. **Location explanation:** shown once per app run (memory only). It is shown again after a restart.
10. **Small screens:** at 360 dp and text scale 1.3, the leg buttons sit below the half-open sheet's first screen, so the driver scrolls or drags the sheet. There is no overflow (layout test).

## Remaining Uncertainty

- **Wrong password → 500 (NOT_VERIFIED):**
  - by static reading, `BadCredentialsException` reaches the generic handler, so the app would show "Không kết nối được máy chủ" instead of the credentials message (`ui-design.md` §4.2);
  - not exercised against the running API;
  - a backend fix would belong to a separate work item.
- **P1b contract (NOT_VERIFIED):**
  - parsing of `geometry_to_next`, `instructions_to_next` and `zone_names` follows `context.md` §2 (planned P1b) with the units metres and milliseconds;
  - it was not checked against a real P1b response, because P1b is not merged;
  - the decoder assumes precision 1e5 and `[lat, lon]` order, as specified.
- **Device behaviour (NOT_VERIFIED):** secure storage on a real Keystore, the geolocator permission flow and stream, the `tel:` launch on Android 11+ (package visibility; the app uses `launchUrl` without `canLaunchUrl`, so no `<queries>` entry was added), and OSM tiles on the emulator.

## Lesson Candidates

For `docs/engineering/LESSONS.md`. They are not written there, because `docs/` is out of this task's scope:

1. **Riverpod 3 retries failed providers by default.**
   - Effect: error UIs appear late, and widget tests wait on the retries.
   - Fix: set `ProviderScope(retry: (_, _) => null)` in the app and in tests.
   - Also: duplicate overrides of one provider in a `ProviderScope` fail with an assertion; give the test harness a parameter instead.
2. **Kotlin incremental cache failure across drives.**
   - Trigger: the Flutter pub cache is on `C:` and the project on `E:`.
   - Effect: the Android build fails with "Could not close incremental caches".
   - Fix: `kotlin.incremental=false` in `android/gradle.properties`, or put `PUB_CACHE` on the project drive.
3. **Android Studio run configurations.**
   - Running Flutter code with a Dart command-line run configuration gives `dart:ui` "isn't a type" errors.
   - Fix: use the Flutter plugin with the SDK path set.
4. **NDK installation.** Install the NDK from the SDK Manager ("Show Package Details"), not through a CLI wrapper that splits the package name.
5. **Widget tests and sheets.**
   - Content of a `DraggableScrollableSheet` is built lazily.
   - Use `scrollUntilVisible` on the sheet's `Scrollable`, or a tall test surface, before tapping widgets low in the sheet.
6. **Workflow scope check during builds.** `workflow.mjs recover` reported `EBUSY` while Gradle held files under `build/`. Run it when no build is running.
