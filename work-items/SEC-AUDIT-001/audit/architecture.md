# Architecture and Trust Boundaries

SEC-AUDIT-001 reviews a branch-based logistics routing system. A branch represents a company. Planners create and import orders, manage depots, vehicles and drivers, submit route-optimization jobs, review solutions, check low-emission-zone compliance, and dispatch selected routes. Drivers read their assigned route. Orders and dispatch data can contain customer names, phone numbers, street addresses and coordinates. A CUSTOMER role is present in the API model, but its intended capabilities require source verification. Branch administration is described as out-of-band in local architecture documents. No comparable routing implementation or independent local security oracle is documented.

The in-scope system has three application components. `GVRP_Entry_API` is a Java/Spring service that authenticates users, applies branch ownership checks, persists business data and calls the engine. `GVRP_Engine_API` is a Java/Spring service using GraphHopper/jsprit for routing. `GVRP_Entry_client_v2` is an Angular SPA using browser storage and HTTP APIs. `.github` contains CI/dependency automation; root configuration scope is `.gitignore`, `.cbmignore`, and `.mcp.json`. The two Maven APIs have distinct Spring Boot parent versions; the client is Angular 18. Local docs show MySQL, a GraphHopper graph/result spool, and integrations for geocoding, mail, Slack webhooks, OSRM and map tiles. They do not establish deployed profiles, ingress, TLS, firewall, secret injection, or provider controls.

Human trust boundaries include anonymous visitors, authenticated PLANNER and DRIVER users, and service-to-service callbacks. Entry's source-visible security rules permit selected auth, docs, health and callback paths; driver paths require DRIVER and the remaining `/api/v1/**` paths require PLANNER. JWT authentication reloads the user, and many business services derive branch scope from the authenticated principal. Callback routes rely on a shared API-key filter at the Entry boundary. Entry-to-Engine calls and Engine endpoints require focused review; repository code does not establish live reachability or network isolation. Browser guards and stores are client-side controls and do not replace server authorization.

Important input and lifecycle paths include REST path/query/body inputs; CSV/JSON/text order imports; GeoJSON zone inputs; optimization job submissions; Engine progress/result/cancel/resend/evaluate/legs operations; Engine callbacks that persist solutions and routes; client local/session storage and URL-driven identifiers; CI workflow and dependency inputs. Source reconnaissance found configured file-size checks for order imports and a client-side zone-file limit, but these do not establish total request, row-count, nesting, solver or runtime limits. The smallest source-visible controls and parallel paths are recorded in `coverage-ledger.json`.
